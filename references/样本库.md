# 中文压缩规范 · 样本库

每组四栏：原始输出、压缩后、删了什么、保住了什么。四组对应四档语体。

## 组 1 · 技术排查（正式书面）

**原始**（约 200 字，LLM 典型三段式）

> 好的，关于你提到的筛选下拉框不显示选项的问题，我来帮你分析一下。
>
> 首先，这个问题通常是由于组件在数据加载完成之前就进行了渲染，导致下拉选项为空。这是一个比较常见的前端时序问题。
>
> 其次，你可以尝试在 useEffect 中添加依赖项，确保数据加载完成后再渲染组件。这样就可以解决大部分类似问题。
>
> 最后，需要注意的是，这个问题在移动端可能会更明显一些。
>
> 综上所述，核心的修复点在于数据加载与渲染的时序问题，希望对你有帮助。

**压缩后**

> 筛选项为空通常是时序问题：组件在数据到达前就渲染了。
>
> 修法是在 useEffect 里加依赖项，确保数据加载完成后再渲染。移动端同样受影响，根因相同。

**删了什么**

| 删掉的 | 属于哪类 |
|---|---|
| 「好的」「我来帮你分析一下」 | A 空转声明 |
| 「首先」「其次」「最后」 | B 结构套壳 |
| 「这是一个比较常见的前端时序问题」 | C 重复，与首句同义 |
| 「这样就可以解决大部分类似问题」 | C 空转，不给新信息 |
| 「需要注意的是」 | A 空转声明 |
| 「综上所述，核心的修复点在于…」 | C 结论换词重说 |
| 「希望对你有帮助」 | A 空转声明 |

**保住了什么**

「通常」（不确定性）、移动端影响范围、根因、修法及修法的目的。字数从约 200 降到 66，删的全是零信息句。

## 组 2 · 教学步骤（日常书面）

**原始**

> 下面我来详细说明一下如何配置这个环境。
>
> 第一步，你需要先安装 Node.js。这里需要注意的是，Node.js 的版本最好在 18 以上，否则可能会出现兼容性问题。安装完成后，你可以通过 node -v 来验证是否安装成功。
>
> 第二步，安装依赖。在项目根目录执行 npm install 即可。这里有一个小提示，如果安装很慢，可以换用国内镜像源。
>
> 第三步，启动项目。执行 npm run dev，然后在浏览器打开 localhost:3000 就可以看到效果了。
>
> 以上就是全部步骤，希望对你有所帮助。

**压缩后**

> 配置环境三步。
>
> 1. 安装 Node.js。版本需 18 以上，低于 18 会出现兼容性错误。装完用 `node -v` 验证。
> 2. 在项目根目录执行 `npm install`。安装慢时换国内镜像源。
> 3. 执行 `npm run dev`，浏览器打开 `localhost:3000`。

**删了什么**

开场预告「下面我来详细说明一下」、「这里需要注意的是」、「这里有一个小提示」、「以上就是全部步骤，希望对你有所帮助」。全部是 A 类与 B 类。

**保住了什么**

三步本身、每步的验证方法（`node -v`）、版本门槛（18 以上）、失败处理（装慢了换镜像）。这些属于可操作性信息，优先级 3，压缩不许碰。

**这组还有个缺口要标出来**：原文没有「第一步报错怎么办」。这属于内容缺失，不属于冗余。压缩不能凭空补内容，补内容由内容生成环节负责。

## 组 3 · 口语化解释（口语）

**原始**

> 这个问题其实说复杂也复杂，说简单也简单。简单来说呢，就是你的数据还没到，界面就已经画出来了，所以看到的是空的。你只要让界面等一下数据，就好了。说到底还是一个时序的问题。
>
> 希望这个解释能让你明白。

**压缩后**

> 说白了就一句：数据还没到，界面先画出来了，所以是空的。让界面等一下数据就行。
>
> 这本质上是时序问题。

**删了什么**

「其实说复杂也复杂，说简单也简单」（纯空转）、「希望这个解释能让你明白」（A 类）、「说到底还是」与「就一句」重复。

**保住了什么**

「说白了」「就一句」是语用标记，在口语档里它们标记「我给你一句人话」，有功能。若按正式书面档处理，这两处会被当冗余删掉，句子会变硬。这是四档语体唯一的作用点。

## 组 4 · 网络文案（网络用语与梗）

**原始**

> 今天给大家分享一个超级实用的工具！这个工具真的非常非常好用，可以帮你在几秒钟内完成以前需要几个小时才能做完的工作。效率提升真的是肉眼可见！强烈推荐大家试一试，相信你一定会爱上它的！

**压缩后**

> 今天分享一个超级实用的工具。它能在几秒内完成以前要几小时的工作，效率提升肉眼可见。强烈推荐试一试。

**删了什么**

「真的非常非常好用」（反复强调，不给新信息）、「相信你一定会爱上它的」（对读者的预测，不承载信息）、「给大家」「真的」各一处。

**保住了什么**

「超级」「强烈」「肉眼可见」。这三处按内容判据同样是强度词，不承载信息。但这一档合法：它们承担情绪，而这一档的首要任务是把情绪传到位。

## 附 · 压缩过度的反例

**原始**（155 字，与组 1 同源）

> 关于你提到的筛选下拉框问题，我分析了一下。这个问题通常是由于组件在数据加载完成之前就进行了渲染，导致下拉选项为空。我建议你在 useEffect 中添加依赖项，确保数据加载完成后再渲染组件。另外，这个问题在移动端可能会更明显一些。综上所述，核心修复点是数据加载与渲染的时序问题。

**正确的压缩**（用户本人版本，约 100 字）

> 关于筛选下拉框问题，这通常是由于组件在数据加载完成之前就进行了渲染，导致下拉选项为空。
>
> 它核心修复点在于数据加载与渲染的时序问题。可以在 useEffect 中添加依赖项，确保数据加载完成后再渲染组件。
>
> 另外，这个问题在移动端可能会更明显一些。

**压缩过度**（55 字，被否）

> 筛选项为空是时序问题：组件在数据到达前就渲染了。修法是给 useEffect 加数据依赖，让渲染等数据。移动端同样受影响，根因相同。

**过度在哪**

| 被删的 | 违反了哪条 |
|---|---|
| 「通常」改成断言 | 优先级 2 不造假 |
| 删掉「确保数据加载完成后再渲染」 | 优先级 2，省掉了修法的目的 |
| 删掉「关于筛选下拉框问题」 | Given-New 入口丢失，属于优先级 2 |

从 155 到 100，删的是零信息句。从 100 到 55，删的是信息。字数不是指标。
