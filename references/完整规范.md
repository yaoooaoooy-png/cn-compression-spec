# 中文压缩规范 · 完整正文

版本 v1.1 · 2026-10-26 · 这是唯一定义处，改规则只改这里。

## 一、管什么

**对象**：LLM 输出的中文。

**目标两个量**：
1. 信息密度。每句承载的、读者自己补不出的信息量。
2. 信息结构。结论出现的位置，以及依据与结论的相对次序。

**不管**：人类手写的文本、纯俚语对话语料。这两类不归本规范。

## 二、优先级阶梯

冲突时从上到下服从。排在前面的赢。

| 序 | 规则 | 含义 | 依据 |
|---|---|---|---|
| 1 | 句子完整通顺 | 不许为压字数把句子拆成短语拼接 | 用户硬边界（2026-10-03） |
| 2 | 不造假 | 不许删掉不确定性、来源、口径，把有保留的说法说成断言 | 删掉不确定词改变真值 |
| 3 | 不丢可操作性 | 步骤、验证方法、失败路径完整保留 | 这些信息读者推不出来 |
| 4 | 结论位置 | 按语体档定结论出现在哪里 | 见第七节 |
| 5 | 压缩 | 唯一必须让步的一项 | 压缩是手段，不是目的 |

压缩排在最后，因为它唯一可以做牺牲。前四项任何一项让步都造成信息损失或语法破损，压缩让步只造成文本变长。

## 三、主判据

> 读者若不知道这件事，会不会做错决定？

- 会，它属于细节，一字不动。
- 不会，它属于常识，可以删。

这一条替代「基础不基础」的判断方式。基础与否会吵，会不会做错决定不会吵。

### 用户口径：「太长」指什么（2026-10-26 用户本人确认）

用户判定过长时，指的是两件事，不是字数：

1. **篇幅需要滑屏。** 段落与分节太多，要往下滚才能读完。
2. **找不到重点。** 通篇没有错，但看不出哪一句是关键。

因此压缩的着力点不是删字，是减少分节数、减少并列项数、把结论单独成行。

反例：把一句长话拆成三行短句，字数没减，仍然算变长，因为行数增加了。

## 四、两条路径

| 路径 | 做法 | 允许 |
|---|---|---|
| 删句 | 整句不含信息，整句删掉 | 允许，且无上限 |
| 缩句 | 句子含信息但啰嗦，改写更短 | 允许，但不得降低确定性、不得省掉目的与限定 |

缩句时一旦信息量下降，属于降级，不属于压缩。

**拆句有停止线。** 中文是意合语言，关系靠语序与语境承担，不靠关联词显化。一条关系链拆成两句独立句，关系就断了。拆到「每句一个判断」为止，不再往下拆。

## 五、可删清单（LLM 输出固有癖好）

这些癖好跨语体出现，与技术说明、口语化解释、社交文案的分档无关。

### A 空转声明

| 实例 | 删法 |
|---|---|
| 「值得注意的是」「需要说明的是」「值得一提的是」 | 整句删。后面那句直接说 |
| 「作为一个 AI」「我将从以下三个方面」「下面我来详细说明」 | 整句删。它是元话语，不承载信息 |
| 「希望这个回答对你有帮助」「如有问题随时告诉我」 | 整句删 |
| 结论已给过之后的「总的来说」「综上所述」「一句话总结」 | 整句删 |

### B 结构套壳

| 实例 | 删法 |
|---|---|
| 总—分—总：开头预告要讲什么，结尾复述讲过什么 | 删预告与复述，只留中间 |
| 三点式对称：只有 2 个要点，硬凑第 3 个 | 删凑数项，写 2 点 |
| 标题通胀：两句话的内容套三级标题 | 压平为一段 |
| 列表癖：连续 3 句以内也转成分点 | 恢复成句 |
| 表格癖：2 项对比也做成表格 | 恢复成句 |

### C 重复与对冲

| 实例 | 删法 |
|---|---|
| 先复述提问，再作答 | 删复述 |
| 结论换个词再说一遍 | 删后一遍 |
| 对冲堆叠：「可能」「大概」「在一定程度上」同现 | 只留一个，或换成明确判断 |
| 「在某种意义上」「从某种程度上说」 | 整句删，除非确实要限定 |

### D 双语补注

| 实例 | 删法 |
|---|---|
| 中文术语后必带括号英文 | 读者是中国用户时删括号 |
| 同一概念中英各写一遍 | 只留中文 |

### E 连接词过密

| 实例 | 删法 |
|---|---|
| 「因此」「然而」「此外」「与此同时」每段都出现 | 留逻辑转折必需的，其余删 |
| 「不仅…而且…」「既…又…」空转 | 拆成两个直陈句 |

## 六、不可删清单

每条附一句依据。依据只在此处出现一次。

| 不可删 | 依据 |
|---|---|
| 不确定性标记：「通常」「可能」「约」「多数情况」 | 删掉它改变断言真值。写「通常是由于」与写「是由于」是两个不同陈述 |
| 上下文锚点：「关于筛选下拉框问题」这类引子 | Given-New 信息结构：已知信息是读者进入新信息的入口。删掉等于让读者从半空进入 |
| 具体数字、版本号、来源 | 读者推不出 |
| 统计口径限制：「只统计了 X，未含 Y」 | 读者推不出，且不知道就会错用 |
| 失败路径、风险、例外情况 | 读者推不出，且不知道就会踩 |
| 步骤与每步的验证方法 | 读者推不出，缺一步就做不完 |
| 影响范围（是否波及其他端、其他场景） | 读者推不出，判断处置范围要用 |
| 反直觉结论（他以为 A，实际 B） | 这是他唯一的认知增量 |
| 证据分级（硬数据 / 外部佐证 / 逻辑推断） | 用户要求，且决定结论可用程度 |

## 七、四档语体

语体由用户显式指定；未指定时按产物类型推断。**不靠模型猜语气**——猜错方向稳定偏正式，会把口语化任务压成公文。

| 档 | 典型产物 | 结论位置 | 允许保留的冗余 |
|---|---|---|---|
| 正式书面 | 报告、方案、对外文件、结论段 | 第一句即结论，不带条件 | 目的说明、口径限定。其余全删 |
| 日常书面 | 解释、教程、聊天里的长回复 | 首段内给结论，可带一句关键依据 | 可用一次「换句话说」类换述 |
| 口语 | 口语化解释、对话回复 | 前三句内出现 | 语用标记（「说实话」「可能吧」）、语气词、短句节奏 |
| 网络用语与梗 | 社交文案、标题、玩梗 | 可后置，优先节奏 | 重复、夸张、破格 |

口语与网络用语两行的结论位置是推定，未经确认。

**档位只调「哪类冗余算合法」，不改判据。** 四档共用第三节的主判据。

## 八、结构规则

1. 结论位置按第七节的档位表。
2. 一段只放一条判断链。判断链指「结论 + 它的依据 + 它的限定」，三者是一段。
3. 同类项 ≥3 才允许用列表。2 项写成一句话。
4. 需要逐项对照才允许用表格。
5. 每条依据紧跟在它支撑的结论之后，不集中堆在文末。

## 九、红线（可机器查）

| 红线 | 阈值 | 说明 |
|---|---|---|
| 空转声明命中 | 每千字 ≤ 2 处 | 数「值得注意的是」「综上所述」「希望有帮助」这类词 |
| 首个结论句位置 | 正式书面≤首句；日常书面≤首段 | 人工或规则匹配定位 |
| 列表项数 | 每处 ≥3 项 | 少于 3 项的列表判违规 |
| 中英双写 | 0 处（中国用户） | 术语后括号英文计入 |

**阈值是我的设定值，不是行业标准，可以调。** 先按这组跑，跑出偏差再改数。

## 十、依据（每条一句话，只在此出现）

以下为已确立的理论概念，本次未核对原始文献。用途只有两个：解释规则边界、裁决冲突。不作为权威引用。

| 概念 | 支撑哪条规则 |
|---|---|
| 认知负荷理论：外在负荷可削，内在负荷不可削 | 支撑「删句 vs 缩句」的二分。要削的是外在负荷 |
| Given-New 信息结构：已知信息是新信息的入口 | 支撑「上下文锚点不可删」 |
| 中文的意合特征：关系靠语序与语境承担，不靠关联词显化 | 支撑「拆句有停止线」 |
| 工作记忆容量有限，一条判断链过长即断 | 支撑「一段一条判断链」 |
| 加工流畅性：读者更信任读起来顺的文本 | 支撑「去冗余提升可信度」，同时警告不能为流畅牺牲准确 |

## 十一、自检流程

改完一段输出，按顺序问五遍：

1. 有句子为了变短被拆成短语拼接吗？有，改回去（优先级 1）。
2. 有不确定性、来源、口径被删掉吗？有，加回去（优先级 2）。
3. 步骤、验证方法、失败路径完整吗？不完整，加回去（优先级 3）。
4. 结论位置符合当前语体档吗？不符合，挪（优先级 4）。
5. 上面四条都过了，还能删哪句零信息句？（优先级 5）
